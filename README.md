# Scramble

**Seven letters. Five chances. One daily challenge.**

Scramble is a daily word puzzle. Every day brings a fresh rack of 7 letter tiles and a cross-shaped board dotted with random bonus tiles. Build five words through the center of the board, make every letter count, and see how close you can get to the day's best possible score.

Live at [scrambleworld.com](https://www.scrambleworld.com).

## How to play

1. Each day you get a new board and a rack of 7 tiles. The board has a random set of bonus tiles.
2. Every word must pass through the center tile ⭐ and extend horizontally or vertically.
3. You have 5 attempts. Each accepted word adds to your cumulative score.
4. Words must be at least 2 letters long, each tile can be used once per word, and each unique word can only be played once.
5. Use all 7 tiles in a single word for a **SLAM**, worth an extra 45 points.
6. Your total is compared to the **best possible score**: the sum of the 5 highest-scoring words achievable with the day's tiles and board.

### Bonus tiles

| Tile | Name          | Effect               |
| ---- | ------------- | -------------------- |
| `dl` | Double Letter | Tile's value ×2      |
| `tl` | Triple Letter | Tile's value ×3      |
| `dw` | Double Word   | Entire word score ×2 |
| `tw` | Triple Word   | Entire word score ×3 |

### Result tiers

| % of best possible score | Label               |
| ------------------------ | ------------------- |
| 100                      | Grand Slammer! 💯   |
| 90–99                    | Word Wizard 🧙      |
| 70–89                    | Letter Lover ✨     |
| 50–69                    | Tile Tinkerer 🔡    |
| 0–49                     | Keep Scrambling 🍳  |

## How it works

### Daily puzzle generation

Puzzles are generated by a scheduled Vercel function ([api/generate.ts](api/generate.ts)), configured in [vercel.json](vercel.json) to run at 00:01 in `Pacific/Kiritimati` (UTC+14), so the puzzle for a given date exists before that date begins anywhere in the world.

[api/\_lib/generatePuzzle.ts](api/_lib/generatePuzzle.ts) runs the pipeline:

1. **Pick a rack** — a random 7-letter word from `src/data/word-list.txt` whose letters haven't been used by a previous puzzle, then shuffled ([generateRackLetters.ts](api/_lib/generateRackLetters.ts)).
2. **Build the dictionary** — every word in `src/data/dictionary.txt` (2–7 letters) that can be spelled from the rack ([generateDictionary.ts](api/_lib/generateDictionary.ts), [sub-words.ts](api/_lib/sub-words.ts)).
3. **Claim the date** — a `SET NX` lock on the puzzle date prevents two puzzles being generated for the same day.
4. **Build the board** — a 7×7 cross (one horizontal and one vertical axis of 7 cells sharing a center cell) with 4–10 randomly typed bonus tiles, at least 2 per axis, never on the center.
5. **Score the best words** — every dictionary word is scored in every valid placement to find the top 20 ([bestPossibleWords.ts](api/_lib/bestPossibleWords.ts)).
6. **Store** the resulting `PuzzleEnvelope` in Redis. If anything fails, the date claim and id counter are rolled back.

Redis keys:

| Key                        | Contents                                                  |
| -------------------------- | --------------------------------------------------------- |
| `puzzle:{id}`              | `PuzzleEnvelope` JSON (puzzle, dictionary, top words), 3-day TTL |
| `puzzle:date:{YYYY-MM-DD}` | Date claim token, 3-day TTL                               |
| `puzzles:next-id`          | Puzzle id counter                                         |
| `puzzles:all`              | List of all generated puzzle ids                          |
| `racks:all`                | List of all racks used so far                             |

Two more scheduled functions live alongside it: [api/fix.ts](api/fix.ts) recomputes `topScoringWords` for the stored puzzles, and [api/overwrite.ts](api/overwrite.ts) is a one-off data patch.

### Playing a puzzle

- The client fetches the puzzle matching the player's **local date** through a server action ([src/actions/getPuzzle.ts](src/actions/getPuzzle.ts)). Only the puzzle definition is sent to the browser; the dictionary and top-scoring words stay on the server.
- Tile placement is validated on the client as you go (minimum length, center cell, single axis, contiguity) by the pure functions in [src/context/game-domain.ts](src/context/game-domain.ts), which also compute the live draft score.
- Submitting a word calls the `checkWord` server action ([src/actions/checkWord.ts](src/actions/checkWord.ts)), which re-validates the tiles against the stored rack, re-runs placement validation, checks the word against the puzzle's dictionary and returns the authoritative score.
- When the puzzle is completed, `getResults` ([src/actions/getResults.ts](src/actions/getResults.ts)) returns the top-scoring words, the best possible score and the day's SLAMs for the results and review screens.

### Scoring

Letter values are defined in [api/\_lib/alphabet.ts](api/_lib/alphabet.ts). A word's score is the sum of its letter values (with `dl`/`tl` applied per tile), multiplied by any `dw`/`tw` tiles it covers, plus 45 points for a SLAM.

### Progress and streaks

There are no accounts. Progress and streak are kept in `localStorage` ([src/context/game-storage.ts](src/context/game-storage.ts)) under `scramblegame:progress` and `scramblegame:current-streak`. The streak increases when you complete consecutive puzzles and resets if you skip a day or give up.

## Project structure

```
api/                        Vercel scheduled functions (outside the Next.js app)
├── generate.ts             Daily puzzle generation
├── fix.ts                  Recomputes top-scoring words for stored puzzles
├── overwrite.ts            One-off data patch
└── _lib/                   Puzzle generation, dictionary building, scoring
src/
├── actions/                Server actions: getPuzzle, checkWord, getResults
├── app/                    App Router entry: layout, page, global styles
├── components/
│   ├── board/              Game board and board tiles
│   ├── letter-tray/        Rack of draggable letter tiles
│   ├── attempts-panel/     Words played so far
│   ├── layouts/            Start, Game and Results screens, give-up dialog
│   ├── how-to-play/        Rules dialog
│   ├── header/, footer/    Desktop and mobile chrome
│   └── ui/                 shadcn primitives (button, dialog, toast)
├── context/                Game state: provider, hooks, domain logic, storage, types
│   └── __tests__/          Vitest suites and fixtures
├── data/                   Word lists and static copy (rules, hints, result tiers)
├── game-config/            Game constants (attempts, SLAM bonus, storage keys)
├── fonts/                  Local display font
└── lib/                    Utilities (cn, random helpers)
```

Game state lives in [src/context/GameContext.tsx](src/context/GameContext.tsx), which composes three hooks:

- `usePuzzleOfTheDay` — loads the puzzle for the local date
- `useRackBoardInteractions` — drag-and-drop and click placement of tiles
- `useGameProgressActions` — start, submit, give up, and streak updates

## Getting started

### Prerequisites

- Node.js 20+
- Yarn 1.x (`packageManager` is pinned to `yarn@1.22.22`)
- An Upstash Redis database (or Vercel KV store)

### Setup

```bash
yarn install
```

Create a `.env` file at the project root with your Redis REST credentials. On a linked Vercel project, `vercel env pull .env` will do this for you.

```bash
KV_REST_API_URL=...
KV_REST_API_TOKEN=...
```

Then start the dev server:

```bash
yarn dev
```

Open [http://localhost:3000](http://localhost:3000).

> The app shows "No puzzle is available for today" unless Redis holds a puzzle for your current local date. Puzzles are created by the scheduled function on Vercel, so the simplest way to get one locally is to point `.env` at a database the deployed schedule writes to.

### Scripts

| Command           | Description                    |
| ----------------- | ------------------------------ |
| `yarn dev`        | Start the Next.js dev server   |
| `yarn build`      | Production build               |
| `yarn start`      | Serve the production build     |
| `yarn lint`       | Run ESLint                     |
| `yarn test`       | Run the Vitest suite once      |
| `yarn test:watch` | Run Vitest in watch mode       |

Tests live in `src/context/__tests__/` and cover the domain logic, storage and the game hooks.

## Deployment

The project deploys to Vercel. [vercel.json](vercel.json) registers the functions in `api/` as scheduled triggers, and the Redis environment variables must be set on the project. Vercel Analytics is only enabled in the production environment.
